Problem: 3 pairs of copy-paste handlers — GetUSD/GetEUR, GetOfficialUSD/GetOfficialEUR, GetUSDHistory/GetEURHistory — are identical except for the currency string. ~60 lines of pure duplication.

Solution: Extract a getLatest(currency), getOfficial(currency), and getHistory(currency) helper. Each handler becomes a one-liner that delegates with the currency argument.

  • • locality: all rate-serving logic in one function per shape
  • • leverage: one fix applies to both currencies
  • • interface shrinks: 8 exported methods → 3 + helpers

Fix the NotFound asymmetry in Official endpoints

Strong bug
internal/handler/rate_handlers.go:58-80

Before

GET /dollars → 200 + []
GET /dollars/official → 500 Internal Server Error

Same condition, different behavior. The Official endpoint passes ErrNotFound to presenter.Error() which maps it to 500.

After

GET /dollars → 200 + []
GET /dollars/official → 404 Not Found

Both endpoints handle ErrNotFound consistently. Official returns 404; list returns empty array.

Problem: GetOfficialUSD and GetOfficialEUR don't handle domain.ErrNotFound — they pass it to presenter.Error() which returns 500 instead of 404.

Solution: Add the same ErrNotFound check that GetUSD/GetEUR already have, returning a 404 with a clear message.

  • • locality: error handling lives in one place per endpoint shape
  • • leverage: fix once, both currencies covered
  • • contract: API consumers get predictable status codes

After — split by concern

classifyError(err) → Code + Status

Each function has one job. Table-driven classification replaces nested conditionals.

Problem: Error() is 90 lines mixing error classification, timeout detection via string matching, HTTP status mapping, and response writing. Hard to test in isolation.

  • • locality: timeout logic in one testable function
  • • leverage: new error types added to table, not nested if-else
  • • interface shrinks: Error() becomes ~20 lines

Problem: The scraper imports apierrors to wrap errors with NewProviderError(). This leaks the HTTP concern into the scraping adapter — a port should only know about domain types.

Solution: Add domain.ErrProviderUnavailable sentinel. Scraper returns domain errors. The presenter (or usecase) maps them to apierrors.ProviderError.

  • • seam: scraper only depends on domain — proper port direction
  • • leverage: presenter maps once, all callers benefit
  • • testability: scraper test assertions check domain errors, not API shapes
⚠ Does not contradict ADR-0001, but the current design was accepted as-is. This is a natural deepening.

Remove the Presenter's direct dependency on domain errors

Worth exploring ports & adapters
internal/presenter/presenter.go:86-176 
              flowchart LR

                P -.leak.-> D2["domain.ErrInvalidInput"]

                classDef leak stroke:#dc2626,stroke-width:2px

Problem: The presenter checks for domain.ErrNotFound, domain.ErrInvalidInput, and domain.ErrDuplicateRate directly. In hexagonal architecture, the presenter is an outbound adapter — it should only know about apierrors.Error types, not domain sentinels.

Solution: Map domain errors to apierrors.Error in the usecase layer (or a dedicated error-mapping adapter). The presenter receives only apierrors.Error and maps to HTTP status. Combine with Candidate 4 for a clean error flow: domain → apierrors → presenter.

  • • seam: presenter depends only on apierrors, not domain
  • • leverage: domain errors can change without touching presenter
  • • testability: presenter tests use apierrors only

Exclude /health from auth middleware

Speculative in-process
internal/http/router/router.go:35 
              flowchart LR
                LB["Load Balancer"] -->|GET /health| R["Router"]
                R -->|"auth (API key required)"| A["Auth Middleware"]

                classDef leak stroke:#dc2626,stroke-width:2px

Problem: The auth middleware is applied globally. /api/v1/health requires an API key. Load balancer probes and uptime monitors typically hit health endpoints without credentials.

Solution: Skip auth for /health by checking the request path in the auth middleware, or apply auth selectively to rate endpoints only.

  • • locality: health check logic stays in one place
  • • leverage: LB probes work without credential management

Top recommendation

Collapse the USD/EUR handler pairs (Candidate 1) + fix the NotFound asymmetry (Candidate 2). These two are tightly related — both live in rate_handlers.go, both are about parameterizing by currency, and the NotFound fix naturally falls out of the deduplication. This is the highest-leverage change: it removes ~60 lines of duplication, fixes a real bug, and makes the handler module deep — one interface, one place to test, both currencies covered.

After that, tackle the error flow candidates (3, 4, 5) as a group — they form a clean chain: scraper → domain errors → usecase maps to apierrors → presenter classifies.
